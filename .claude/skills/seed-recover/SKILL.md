# seed-recover


Read docs/workflows/execution.md. Inspect actual Git/worktree state, current scope,
task/checkpoint, relevant evidence and fresh MCP status. Preserve uncommitted work.
Use targeted context; summarize stage, tests actually run, blockers and next action.
Ask only missing high-impact questions. A changed source/plan needs explicit reconciliation,
not a forged fingerprint. Native client goals may execute approved slices; deterministic
procedures can use seed_tasks.py. Respect budgets, locks and stop signals. Do not report
command success as full application acceptance.

For interrupted decision planning, identify the exact map and active question. When multiple
maps exist, require explicit selection rather than timestamp guesses. Read a bounded handoff
via seed_plan.py or planning_handoff MCP. Verify prerequisite outcomes, current evidence,
claims and expired exceptions before resuming. Do not import a snapshot over a live map;
there is one local authority, and snapshot import restores no leases. Readiness schema 1
requires migration/reapproval. A modified approval fingerprint is not evidence of new consent.

## Integration contract

Use doctor to distinguish declared phase hints from current/stale scope, task and technical evidence. New integrity policy intentionally invalidates old checkpoints. Preserve them, inspect actual work and reverify; do not patch fingerprints. Native-client records are optional recorded observations, not inferred connectivity.

## External research recovery
Read seed_oss.py status/inspect for sources referenced by the active task. A path or version
label is not evidence. Restore a missing verified snapshot using its exact saved identity;
never overwrite a stale cache, silently reacquire a default branch, or forge a new binding
for an old result. Derived graphs can be rebuilt after source/tool changes. Keep this optional
when no external source was used; the normal first-party MCP reader stays root-scoped.
