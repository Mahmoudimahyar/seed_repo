# Integrate into an existing repository

Do not unzip over the working application or run `seed.py init` there. Inspect existing
instructions, scope, Git state, build scripts, tests, and workflows. Preserve uncommitted
changes, use an isolated branch, and compare this release beside the repo.

Choose the needed policies/skills and merge one canonical AGENTS file, not overlapping
bootstrap patches. Existing application paths and stack take precedence over illustrative
templates. Adapt CI to the real commands and environments; do not replace mature checks
with starter tests. Map existing docs/task systems rather than duplicating them.

Review every changed permission, action pin, license/notice, ownership, and server-side
setting. Add tests for the adoption path, verify the actual GitHub checks, and record
what remains unconfigured. If you cannot reconcile a script's expected layout, use the
workflow documents manually rather than declaring the adapter installed successfully.

The local initializer is intentionally for clean template copies only. There is no
in-place migration engine or automatic merge with historical Seed Repo add-ons.

## Reconstruct intent without ratifying bugs
Label observed behavior, documented promises, inferred intent and approved intent separately.
Characterize important existing behavior before risky edits; record defects that should be
changed with reviewed regression tests rather than making every old behavior binding. See
[spec-anchored TDD](../workflows/specifications-and-tdd.md). Do not initialize over a live repo.
