# 0.3.1-rc.1 — integration hardening

A consolidated correction release for the 0.3.0 integration audit. No new external agent
framework, paid service, cloud account, hosted graph or mandatory marketing workflow.

## Corrected handoffs

- Public distribution rejects machine-local configurations and unexpected files against an
  explicit reviewed inventory. Tests exercise validation, packaging and extracted output together.
- Execution integrity is independent of retrieval exclusions; relevant lock/config/evaluation
  inputs invalidate checkpoints. Shared subprocess bounds preserve failures and clean POSIX children.
- Active feature artifacts are registered and bound to scope approval. Technical tests, recorded
  scope, retained starter regressions and optional MCP now have explicit CI consumers.
- Governed tasks pin the exact workflow, referenced manifests and command; preflight denial
  starts no command. Local counters and postchecks are retained without pretending to be a sandbox.
- Prediction artifacts preserve abstention/errors and generating configuration through scoring.
  Comparison rejects unsupported fields and enforces coverage. Old unbound results cannot promote.
- Canonical skill deletion/rename safely retires unchanged generated mirrors; manual edits block.
- Context includes Python module-level gaps, useful relationship priority, canonical-only skills,
  bounded paged source and stale-continuation rejection.
- Doctor derives evidence freshness instead of trusting a phase label. Native-client observations
  remain explicitly recorded, not inferred. SDK protocol tests now assert evidence semantics.

## Compatibility and migration

Existing apps need explicit feature registration, reviewed fresh approval and MCP applicability.
Planner approval can carry sanitized snapshots for clean CI. Old task fingerprints intentionally
require reconciliation, not forced reuse. Existing model-result lists remain exploratory. Read
[upgrading](../upgrading.md) before merging. Never overwrite app code, local configs or approvals.

See [audit closure](../integration-hardening.md) and [validation](../validation.md). No public
GitHub change, native-agent session, paid benchmark, or production deployment is performed by
this release. The official MCP SDK and hosted/client checks must pass where actually installed
before those integrations are claimed verified. Local testing is not an independent security audit.
