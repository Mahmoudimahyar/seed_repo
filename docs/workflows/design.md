# UI and reusable design assets

Activate for an approved UI, not every tool. Start from user goals, realistic content,
information hierarchy, access needs, and reference directions. Ask for product/taste
approval where needed. Research relevant accessible interaction patterns rather than
copying a fashionable layout or treating every gradient as inherently wrong.

Define a small token system for color, typography, spacing, radii, elevation, and motion;
select one compatible primitive/component approach. Use established accessible primitives
where appropriate and verify the composed experience. Capture keyboard/focus rules,
reduced-motion behavior, responsive behavior, and empty/loading/error/success states.

Maintain one component inventory and one asset registry with source files, license,
variants, usage restrictions, and ownership. Reuse brand decisions across web, email,
social, and print when those channels are in scope. Channel-specific output differs:
email client support, contrast, resolution, and print color requirements need adaptation.
Do not assume a web component is directly portable to every channel.

Create a global site/navigation map and per-feature flow definitions, linked to tests.
A design direction is approved before final UI implementation; prototype experiments
must be scoped separately. No logo, font binary, paid stock asset, fabricated chart data,
or public marketing claim is supplied by this starter.
